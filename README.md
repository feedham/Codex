# Bar Member Manager

A local-first Android app for the supplied District Bar Association Kasur directory. The app includes local sign-in, persistent member records, PDF review and update reports, member call/status tracking, and member insights.

## Open and run

Open this folder in Android Studio (Giraffe or newer), allow Gradle sync, and run the `app` configuration on an Android 8.0+ device or emulator. Android Studio installs the required SDK and build tools. No storage permission is required for imports: Android's system document picker grants access only to the PDF or image the user selects. On Android, Call requests Phone permission when needed and places a direct call. Once the call action launches, the member is marked Called and the status is saved locally. Permission denial, an invalid number, or a missing phone app leaves the status unchanged. Called records a call attempt rather than a connected conversation.

Android, Windows, and Chrome use local email-and-password signup and sign-in. Gmail approval, phone numbers, OTP codes, and a verification backend are not required. Existing accounts can sign in with their saved password. Password fields have a right-side eye button to show or hide the value. Save the recovery code shown after signup or the first sign-in after upgrading. Forgot password uses your email and that saved recovery code; it replaces the password and recovery code while preserving member/profile data. To replace a lost recovery code while you still know your password, select Create a new recovery code on sign-in. Accounts created before recovery was added must sign in once to set it up; an email address alone cannot reset a password. Recovery codes apply to the local app/device, and backups exclude them. Update the app in place to retain its saved data.

The first account is created from Sign Up. Passwords are stored as salted PBKDF2 hashes; account records and the member database stay on the device. Profile image and extracted member portraits live in app-private storage/URI grants.

On first launch, the app loads the supplied directory as its built-in member list when the local member database is empty. This includes 2,594 member cards and their 1,807 available portraits; it never replaces a database that already has member records. The Chrome and Windows apps use the same first-run seed.

Both Android and desktop use the supplied DBAKSR logo and blank advocate portrait when a member has no photo in the PDF. The member search matches names, cell numbers (ignoring punctuation), and enrollment dates. Search D.O.E using DD/MM/YYYY (day first), unpadded D/M/YYYY, ISO YYYY-MM-DD, or a year. Each member row shows D.O.E, and the Sort list by control offers Name (A-Z), D.O.E (oldest first), and D.O.E (newest first); missing or invalid dates appear last. The source directory does not provide a CNIC field, so enter it in an advocate profile if needed. Reference Name appears at the end of the advocate profile fields with a grey **No Reference Yet** default. Choose **Add Reference**, enter the name, and press **Submit** to save it. A saved reference can be edited or cleared, is included in backups, and survives PDF updates. The navigation uses the supplied advocate and senior advocate icons and a standard Insights icon.

Open an advocate from the member list to enter or edit CNIC, Area Zone, Gender, and Group Affiliation, then press **Submit**; the values are saved locally and included in backups. Group Affiliation defaults to **Independent Voter** and can be changed to Ittefaq Group of Lawyers, Ittehad Group of Lawyers, or Azad Group of Lawyers. Later PDF imports retain manually assigned profile and group fields. Insights starts with Biometric, Group Affiliation, and Top 20 Earliest Enrollment, followed by the other cards. Call and My Support Status are separate, clickable insight cards. Cards use a compact staggered layout to avoid blank space below shorter cards. The graphs cover Area Zone, chamber, biometric, gender, Group Affiliation, My Support Status, and Call. Selecting a graph category shows its matching members; selecting a member opens the full profile. The D.O.E year-wise enrollment insight shows all years and drills down through month, exact enrollment date, matching members, and full profiles. Dates use month/day/year (ISO dates from backups are also accepted); missing or invalid dates appear in a separate group. Back controls return through each level. The **Top 50 Bar Members List** navigation button follows Bar Members List and opens a separate ranked seniority view with photos and DD/MM/YYYY enrollment dates. It selects up to 50 active members with valid dates, earliest enrollment first, using name and member ID to resolve ties. Select a row to open the full advocate profile and use Back to return. Android uses an evenly spaced navigation icons with short labels at the top, including Top 50; the duplicate Home shortcut is removed. The senior-member list also opens profiles, and the latest import differences remain visible in the overview. Use **Backup / Restore the List** to save a JSON backup containing member records, available portraits, profile/group fields, called and support statuses, and import differences. On the Home screen, the app logo returns to the member list. PDF updates are available from Backup / Restore; the Home screen keeps only search and member navigation. Backups exclude passwords and the sign-in session; restoring replaces the current member list and import history after confirmation. The Windows package uses the DBAKSR logo as its application icon.

The **Credit** navigation item opens a page with Advocate Fahmeed Shaukat Ansari and Advocate M Attique on separate rows, each with the supplied portrait beside the name, in that order.

## PDF assumptions and limits

The supplied PDF uses a two-column directory of advocate cards. The parser treats each uppercase heading before `s/d/w of:` as the member name, `Comp.#` as the stable member key, `D.O.E` as enrollment date, `Cell` as phone, `Off` as office/chamber, `Res` as residence, and `Biometric` as biometric status. Member photos are cropped from the upper-right portrait frame aligned to each heading. Those assumptions are documented next to the parser. The source does not provide a dedicated Area or Gender field; Area can be recognized from residence addresses using the optional Google Maps Geocoding integration described below, while Gender remains unknown rather than inferred from names. Rows missing a member number or enrollment date are flagged for review. The parser expects a text PDF; image-only scans need OCR and will be shown as an empty/unreadable import.

## Build a signed APK

This workspace has a local self-signed release key configured in `keystore.properties`. Build the signed APK with:

```powershell
.\gradlew.bat assembleRelease
```

The release APK is written to `app/build/outputs/apk/release/app-release.apk`. To build a debug APK instead, run `.\gradlew.bat assembleDebug`; output: `app/build/outputs/apk/debug/app-debug.apk` (debug builds are signed automatically with Android's debug key). In Android Studio, open the project and run the `app` configuration or choose **Build > Generate Signed Bundle / APK > APK**.

For a new checkout or a new signing identity, generate a private keystore with `keytool -genkeypair -v -keystore bar-member-release.jks -alias bar-member -keyalg RSA -keysize 2048 -validity 10000`, then set its path and passwords in `keystore.properties`. Keep the same keystore for future updates; these local key files are excluded from version control.

On the phone, transfer the APK, open it, and allow **Install unknown apps** for the file manager or browser that opened it when Android prompts. Review the install prompt and tap Install. Keep the signing keystore: future updates must use the same key.

## Windows and Chrome app

The desktop companion is in `desktop/`. It uses IndexedDB in the local browser, includes the PDF parser as a dependency, and follows the same directory field assumptions. To run it in Chrome, install Node.js 20 or newer, open a terminal in `desktop`, run `npm install --offline=false` once, then `npm start` and open `http://127.0.0.1:4173` in Chrome. It runs fully locally after dependencies are installed.

To recognize areas from member residence addresses, enable the Google Maps Geocoding API and billing in a Google Cloud project, create a key restricted to the Geocoding API (and, where practical, to the machine's public IP), then start the local app with `GOOGLE_MAPS_API_KEY` set in the environment. In PowerShell, run `$env:GOOGLE_MAPS_API_KEY = 'YOUR_KEY'` before `npm start` or `npm run desktop`. In Chrome, choose **Recognize areas** and confirm the disclosure before any addresses or saved Google Place IDs are sent. The server keeps the key out of browser JavaScript and the installed Electron package. Place IDs are saved locally, but returned area labels stay in memory for the current app session and are looked up again after restart. A changed residence address triggers a new address lookup. Geocoding may incur Google Maps Platform charges. The integration filters address requests to Pakistan and chooses the most specific available locality component, then falls back to locality, sub-district, district, or province; unresolved addresses remain blank. Before public distribution, provide the publicly accessible Terms of Use and Privacy Policy required by Google's Geocoding API policies.

To create a Windows installer that bundles Electron and the parser runtime, run `npm install --offline=false` followed by `npm run dist`. The NSIS installer and portable `.exe` are created in `desktop/dist/`. The installer is not code-signed by a commercial Windows publisher certificate, so Windows may show its normal first-run publisher warning.

## Optional SQLite directory backend

See [backend setup](backend/README.md) for the SQLite database, PDF-derived import (2,594 members), authenticated paginated API, and Android directory download. Run `node backend/start.cjs` or double-click `backend/Start Backend.cmd`. Node.js 24 is the only runtime needed; no Docker or database server installation is required. The app still works offline and retains local campaign edits during directory downloads. No cloud service has been provisioned.

Android advocate profiles show Call and WhatsApp Call side by side at equal width. Call starts a normal phone call and marks Called after the phone app launches. WhatsApp Call opens the installed WhatsApp (or WhatsApp Business) chat for that member; use its phone icon or message field there. Merely opening a chat does not mark Called. Pakistani national mobile numbers are converted to +92 format for WhatsApp links; explicit international numbers are preserved.

Android Compose message supports text, one image, and a VCF export of up to 256 selected member contacts. Import the VCF with the phone Contacts app and create the broadcast list inside WhatsApp. Member selection here does not preselect WhatsApp recipients. Recipients and final Send remain in WhatsApp; no automatic sending or delivery tracking is claimed. The top navigation shows labels beneath aligned icons. The member search has a contrasting panel and clear-text action.

Name-based gender suggestions run offline on Android, Windows, Chrome and the local app. Open an advocate profile with no saved gender, review the clearly marked estimate, select Use suggestion (or choose a different gender), and press Submit. Ambiguous names remain unassigned. Existing saved values take priority and manual corrections are preserved by imports, directory sync and backups. The small character n-gram classifier uses curated example names; it has not been validated against confirmed genders in the member directory. It does not send names to a hosted AI service. See NAME-GENDER-MODEL.md.
